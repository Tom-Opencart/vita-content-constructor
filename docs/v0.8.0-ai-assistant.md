# v0.8.0 — Помощник: «Создать по донору»

## 1. Суть

Конструктор остаётся **статическим**: без сети, без ключей, без чтения чужих сайтов.
Весь веб-интеллект — на стороне AI, которого выбирает пользователь (ChatGPT, Claude,
DeepSeek, Perplexity — любой с доступом в веб). Петля:

```
Конструктор: промт = Паспорт возможностей + Донор (URL) + Пожелания + формат ответа
   ↓ «Скопировать промт»
Пользователь: любой AI с веб-доступом читает донора и возвращает JSON проекта
   ↓ вставка ответа в Помощник (или сохранение в .json и обычный импорт)
Конструктор: мягкая починка → валидация → лендинг в канвасе за один шаг
```

## 2. Паспорт возможностей (единый источник правды)

Документ «что умеет конструктор» **генерируется из живого `BlockRegistry`** при
сборке — не пишется руками и не может устареть.

- `src/core/passport.js` — генератор: обходит `BlockRegistry.getList()`, из
  метаданных (`label`, `group`, `fields`, `defaults`, `toHTML`) собирает документ:
  каркас проекта (`vita-constructor-project`, контракт `vcc-v1`), общие поля секций
  (`data.sec`), инлайн-разметку, правила качества, формат ответа; по каждому блоку —
  человекочитаемое описание, поля с типами и один цельный пример (defaults,
  дополненный до реалистичного вида).
- Вшивание в бандл не требуется: паспорт строится в рантайме из уже загруженного
  реестра (та же структура, из которой рисуется палитра редактора).
- Человекочитаемый дамп: `tools/dump_passport.js` пишет `docs/CONSTRUCTOR-PASSPORT.md`;
  гейт сборки `build/build.py` падает, если закоммиченный паспорт ≠ сгенерированному
  (защита от рассинхрона документации и кода).

### Формат промта (конверт)

1. Роль и задача (проектирование структуры страницы для конструктора Виты).
2. **Донор**: URL из поля формы.
3. **Пожелания**: свободная строка пользователя («акцент на тарифы», «без блога»,
   «кнопки form:N только по этим формам») — если заполнена.
4. Паспорт: строгий реестр блоков (тип, назначение, поля с допустимыми значениями),
   правила (один H1, тексты-заглушки-намёки — ремикс, не копия донора; цвета не
   указываются — их задаёт палитра магазина; якоря латиницей; никакого HTML/JS).
5. Формат ответа: **только JSON** `vita-constructor-project`, без markdown-забора
   и пояснений + один мини-пример блока целиком.
6. Ограничение объёма: 6–12 блоков.

## 3. UI: одна кнопка «Помощник»

Точки входа:

- карточка «Создать по донору (AI)» на первом экране — рядом с галереей макетов;
- кнопка в шапке редактора (`fa-magic`, «Помощник»).

Модалка с двумя вкладками:

- **Промт**: поля «Донор (URL)» и «Пожелания», сворачиваемый предпросмотр промта,
  счётчик размера, кнопки «Скопировать промт» (Clipboard API с fallback на
  `execCommand` для file://) и «Скачать промт .txt» (fallback для всех).
- **Ответ AI**: textarea «Вставьте ответ модели», кнопка «Собрать лендинг».

## 4. Приёмник ответа (мягкая починка)

Порядок разбора вставки:

1. Срез markdown-забора: ` ```json … ``` `, ` ``` … ``` `.
2. Если JSON.parse не удался — извлечение от первого `{` до последнего `}`
   (модели иногда добавляют фразу до/после).
3. `JSON.parse` → `vccNormalizeProject` (unknown-типы отбрасываются, пропущенные
   поля добирают дефолты).
4. **Человеческие ошибки** (до нормализации, поверх сырых данных):
   - неизвестный тип блока — с подсказкой ближайшего имени из реестра
     (минимальное расстояние Дамерау—Левенштейна): «тип "tarifs" не существует —
     ближайший: "pricing"»;
   - не тот формат: массив без обёртки → оборачивается автоматически;
   - чужой контракт → сообщение с ожидаемым значением;
   - больше 20 блоков → предупреждение (не блокировка);
   - пустой ответ → тост.
5. Успех: `VccStore.setProject` (undo-чекпойнт ставится сам), тост «Лендинг собран:
   N блоков», модалка закрывается.

## 6. Критерии приёмки

- Паспорт содержит 100% блоков реестра с полями и примерами; правка блока без
  обновления паспорта ломает сборку.
- Промт содержит: контракт, донор, пожелания, строгий формат ответа; размер ≤ 25 КБ
  (без паспорта донор+пожелания дают ~1 КБ).
- Копирование работает на HTTPS (Clipboard API) и file:// (fallback).
- Ответ AI с ` ```json `-забором, преамбулой «Вот структура…» и висячими запятыми —
  собирается в лендинг; unknown-тип даёт человеческую ошибку с ближайшим именем.
- Обычный импорт `.json` работает как раньше (смоук v0.7.0 зелёный).

## 7. Выносится на потом

- BYOK / прямые вызовы AI из конструктора — исключено архитектурно.
- Чтение донора внутри конструктора (ридеры/прокси) — исключено.
- Аудит проекта (линтер качества), мастер по брифу, история промтов, английский
  паспорт — отдельные фичи поверх Помощника.
