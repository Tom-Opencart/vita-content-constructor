# Витрина-конструктор v0.5.0 «Лендинги» — спецификация внедрения

Статус: черновик для утверждения владельцем. Документ — полный отчёт исследования
(два бенчмарка-лендинга) + точная спецификация каждой функции: модель данных,
поля редактора, экспортный HTML, CSS-классы, тёмная тема, требования к стороне
темы, порядок сборки и синхронизации, чек-лист проверки.

Реализация в двух репозиториях: конструктор (`vita-content-constructor`, этот
репозиторий) + шаблон
Виты (`vita-main`, приватный). Контракт — `vcc-v1` (аддитивная эволюция).

## 1. Исследование эталонов

### 1.1. Каталог лендинг-секций (публичный демо-каталог «primer1»)

Страница-каталог из 33 секций `lp-*`. Снятые закономерности, которые переносим:

- Каждая секция — полноширинный блок со своим фоном: `bg-none` / `bg-light` /
  `bg-dark` / `bg-primary` → ложится на нашу схему токенов Виты (см. §4.3).
- Типовой набор секций: hero с фоном-картинкой и оверлеем, логотипы партнёров,
  «преимущества» сеткой иконка+заголовок+текст, медиа+текст (2 колонки),
  шаги/таймлайн, числа-статистика, отзывы, команда, документы/сертификаты,
  CTA-полоса, контакты, соцсети, чек-лист, тарифы, FAQ, разделитель, SEO-текст.
- Кнопки в каждой продающей секции: 1–2 кнопки (solid + ghost/outline).
- Заголовок секции — трёхслойный: надзаголовок-«бровь» (eyebrow), H2, подзаголовок.

### 1.2. SaaS-лендинг (публичное демо demo-ydy, «Yoonche»)

Реальный лендинг, подтвердивший паттерны (два блока владелец отметил явно):

- **Steps/таймлайн** («Вот этот блок я бы взял») — нумерованные шаги с
  вертикальной линией-таймлайном, заголовок + текст на шаг.
- **Pricing** («И вот этот») — карточки тарифов: название, цена (можно диапазон
  «от 990 ₽»), период, список «Всё из тарифа X» (наследование текстом фич,
  отдельной механики не нужно), выделенная карточка «рекомендуем», кнопки.
- Акцентные слова в H1 (цветом) → наш inline-`==акцент==` (§5.5).
- Фоновое видео в hero (muted+loop+autoplay+playsinline, JS не нужен для
  самого видео, но нужен для вставки — см. §7 рантайм).
- Бейджи доверия (оплата/доставка/гарантии) и trust-строки под кнопками.
- Типографика важнее картинок: много текста, мало изображений.

### 1.3. Что в системе Виты УЖЕ есть и НЕ дублируется

- Товары, баннеры/слайдеры, галереи, отзывы, FAQ, формы, новости — выводятся
  **модулями в макете (Layout)** и шорткодами темы: `[vita_gallery]`,
  `[vita_faq]`, `[vita_form]`, `[vita_news]`, `[vita_testimonial]`,
  `[vita_html]…[/vita_html]`, `[vita_news_gallery]`.
  Регистр шорткодов: `upload/catalog/controller/extension/module/vita_theme.php`.
- Готовые блоки-шорткоды конструктора: `vita_faq`, `vita_form` (мок в редакторе,
  литеральный шорткод в экспорте, пикер ID из каталога пресета).
- Баннер/слайдер/товары в скоуп не входят — решение владельца: «Я могу вывести
  Баннер, слайдер, товары итп с помощью обычного вывода в Макете. Не учитываем это».
- Калькуляторы и иная сложная JS-механика — вне скоупа (решение владельца).

**Вывод:** конструктору не хватает «статического скелета» лендинга — секций,
которые не являются живыми модулями темы: hero, шаги, тарифы, команда и т.д.
Именно они и добавляются в v0.5.0.

## 2. Инварианты (что ломать нельзя)

1. **Контракт vcc-v1 аддитивен.** Ни один существующий класс `vcc-*`, атрибут
   `data-vcc-*` или поведение экспорта не меняются и не удаляются — на живых
   витринах уже лежит импортированный контент. Новые блоки только добавляют
   классы. `vcc-v2` объявлялся бы только при смене семантики — её нет.
2. **Токен-контракт.** `css/export.css`: ни одного hex в правилах; все цвета —
   `var(--mp-*, fallback)`, fallback === значение в `:root` vita.css
   (см. таблицу §4.2). Разрешены литеральные `rgba()` только для нейтральных
   оверлеев/тени-теней (прецедент: значения shadow-токенов в токенах Виты —
   `rgba(0, 0, 0, .05)` и т.п.). Гекс-линт билда это проверяет.
3. **Экспорт — только статический HTML.** Никакого JS в экспортируемом контенте.
   Интерактив блоков (табы, TOC) обеспечивает рантайм темы в
   `upload/catalog/view/theme/vita/javascript/common.js` (функция
   `initVccBlocks`) — новый интерактив v0.5.0 добавляется туда же (§7),
   согласованным коммитом в обе репы.
4. **Синхронизация CSS.** `css/export.css` ≡
   `upload/catalog/view/theme/vita/stylesheet/vita-content-constructor.css`
   (байт-в-байт, гейт `vcc_sync_gate` в билде темы). Любое изменение export.css
   → `python build/build.py` → `python build/sync_to_theme.py sync` → коммит
   ОБЕИХ реп в одной сессии → `sync_to_theme.py check`.
5. **Модель данных плоская.** `vccNormalizeBlock` не умеет рекурсивных детей —
   поэтому НЕ делаем контейнерный блок «row/col с вложенными блоками». Вместо
   него — блок `columns` и структурированные поля внутри блоков (§5.4, §6.18).
6. **Стиль кода конструктора:** ES5 (`var`, без стрелок/let/const), TAB,
   одинарные кавычки, `'use strict'` в каждом файле, FA4-иконки, никаких новых
   внешних зависимостей.
7. **Два пути внедрения — экспорт лосся одинаково на обоих.** Стандартный
   поток владельца: экспорт конструктора вставляется в модуль «Вита — HTML»
   (`vita_extra_html`) **в режиме исходного кода** (путь A, ничего не
   фильтруется — админ доверенный). Второй путь — кнопка «Импорт
   `content-*.html`» в UI модуля: файл проходит `VitaContentSanitizer::clean`
   ДО вставки в редактор (путь B). Экспорт обязан использовать только
   §3-разрешённые теги/атрибуты/схемы, чтобы оба пути давали
   идентичный результат. Самоё содержимое экспорта не должно нести
   `script`/`iframe` никогда (см. §3.0).
8. **Публичная гигиена репы.** Никаких файлов темы, доменов живых магазинов,
   токенов, клиентских данных. В примерах — только вымышленные данные.
9. **OpenCart:** без миграций (только свежая установка), `<code>` в install.xml
   не трогаем, инсталлер копирует и никогда не удаляет.

## 3. Пути внедрения и проверенные факты о санитайзере

### 3.0. Реальные пути доставки контента на витрину (проверено по коду, 2026-09-20)

- **Путь A — стандарт владельца:** экспорт конструктора → вкладка модуля
  «Вита — HTML» → Summernote, режим исходного кода → сохранить. Admin-save
  пишет POST как есть (`admin/controller/extension/module/vita_extra_html.php:12-31`),
  витрина печатает raw (`catalog …/module/vita_extra_html.php:25` + twig
  `{{ vita_html }}`). Фильтра НЕТ — админ доверенный. Сюда же физически можно
  доклеить сервисный iframe/script виджета руками (и есть штатные поля модуля
  «Custom CSS»/«Custom JS», twig:4-11/21-28).
- **Путь B — импорт файла:** кнопка загрузки `content-*.html` в UI модуля →
  `import_content` (admin-контроллер, строки 382-416) →
  `VitaContentSanitizer::clean()` → очищенный HTML подставляется в редактор.
  Санитайзер вызывается РОВНО в этом месте во всей теме — больше нигде.
- **Правило контракта:** экспорт конструктора проектируется под whitelist
  пути B. Тогда A и B дают побайтово одинаковый результат, а «сырые» теги
  (iframe/script) в экспорте не появляются ни при каком пути — иначе файл,
  импортированный через B, тихо теряет половину блоков.

Источник фактов по санитайзеру: `upload/system/library/vita/security/content_sanitize.php`
(проверено по коду, 2026-09-20).

### 3.1. Разрешённые теги

`h1..h6, p, div, span, br, hr, strong, b, em, i, u, s, sub, sup, code, pre,
ul, ol, li, blockquote, figure, figcaption, table, thead, tbody, tr, th, td,
a, img, details, summary, nav, footer, button`

**Нет:** `section`, `video`, `source`, `picture`, `iframe`, `form`, `input`,
`svg`. Неизвестный тег разворачивается (`unwrap`) — дети остаются.

### 3.2. Разрешённые атрибуты

- все теги: `class`, `dir`, `lang`;
- `a`: `href`, `title`, `target`, `rel`, `data-agree`;
- `img`: `src`, `alt`, `title`, `width`, `height`, `loading`;
- `details`: `open`; `button`: `type`; `ol`: `start`, `type`;
- единственный data-префикс: **`data-vcc-`**; классы: `vcc-*` + состояния
  `is-active`.

**Нет:** `id`, `style`. → Якоря и динамические фоны невозможны как атрибуты;
живут только через `data-vcc-*` + рантайм темы (§7). Это уже подтверждено
механикой TOC: рантайм сам навешивает `id="vcc-h-N"` на заголовки ПОСЛЕ
санитайзера (`common.js`, `initVccBlocks`).

### 3.3. `href` (`safeHref`)

Пропускает: `#…`, `https?://…`, `/…`, `image/…`, `agree:<число>` (превращается
в `data-agree`). Прочее → `href` снимается, текст ссылки остаётся (грациозная
деградация). → Для `[текст](form:N)` нужен аддитивный `form:(\d+)`-branch,
зеркальный `agree:` (§7.4). До обновления темы кнопка `form:N` деградирует в
обычный текст — безопасно.

### 3.4. Выводы для проектирования

| Потребность | Решение | Почему |
| --- | --- | --- |
| Обёртка секции | `<div class="vcc-section">` | `section` вырезается |
| Фон-картинка/видео секции | `data-vcc-bg` / `data-vcc-bg-video` + рантайм | нет `style`, нет `video` |
| Якорь секции | `data-vcc-anchor` + рантайм навешивает `id` | нет `id` |
| Оверлей фона | класс + rgba в export.css | ок |
| Модальная кнопка формы | `href="form:N"` (+ тема §7.4) | прецедент `agree:` в safeHref |
| Видео из сервисов (YouTube/Vimeo/Rutube…) | блок `video`: `data-vcc-video` + рантайм строит iframe (§6.20, §7.5) | `iframe` вырезается, но рантайм-элемент создаётся ПОСЛЕ санитайзера |
| Кнопка-`button` | не используем — `<a class="vcc-btn">` | button без формы бесполезен |

### 4.3. Фон секции → токены (схема бенчмарка bg-none/light/dark/primary)

| `bg` | CSS-правило секции | Текст внутри |
| --- | --- | --- |
| `none` | без фона | наследуется |
| `light` | `background: var(--mp-bg-subtle, #f8fafc)` | обычный |
| `surface` | `background: var(--mp-bg-surface, #ffffff)` | обычный |
| `primary` | `background: var(--mp-primary, #8C9D93)` | `color: var(--mp-text-inverse, #ffffff)` (весь текст секции, ссылки — lighten через подчёркивание) |
| `image` | как `surface` + фон-картинка из рантайма (`data-vcc-bg`) | зависит от оверлея |
| `video` | как `image` (poster = тот же `data-vcc-bg`) | то же |

`primary` в тёмной теме не флипается — `--mp-primary` в обеих темах один,
`--mp-text-inverse` флипается корректно.

### 4.4. Тёмная тема: аудит и аддитивные правила

Правило: компонентный фон/текст используем ТОЛЬКО из фликающихся токенов
(4.2) либо схемой 4.3. Прямых переопределений `[data-theme="dark"]` в v0.5.0
ровно два (прецедент существующего `[data-theme="dark"] .vcc-alert--info`):

1. `[data-theme="dark"] .vcc-plan--featured { background: var(--mp-bg-hover, #38343E); }`
   — выделенный тариф построен на `--mp-primary-light`, у которого нет dark-оверрайда.
2. `[data-theme="dark"] .vcc-section--overlay::before { background: rgba(0, 0, 0, 0.65); }`
   — в темной теме оверлей светлого poster-изображения усиливается (контраст текста).

Всё остальное обязано работать без dark-правил. Если в процессе оказывается,
что какому-то блоку нужно третье правило — это сигнал, что выбран
нефликающийся токен; сначала пересмотреть выбор.

## 5. Общая фундаментальная часть

### 5.1. `vcc-section` — обёртка (не блок, а каркас каждого лендинг-блока)

Каждый новый «широкий» блок экспортируется как одна полноширинная секция
(Tilda-модель, соответствует каталогу 33 `lp-*`-секций):

```html
<div class="vcc-section vcc-section--bg-{bg} vcc-section--pad-{pad}[ vcc-section--w-{width}][ vcc-section--overlay][ data-vcc-anchor="{slug}"][ data-vcc-bg="{путь}"][ data-vcc-bg-video="{url}"]>
  <div class="vcc-section__inner">            <!-- затемнение фона при оверлее -->
    <div class="vcc-container">               <!-- width: узкий/обычный контент -->
      <!-- заголовок секции, §5.2 -->
      <!-- тело блока, классы vcc-{блок}__* -->
    </div>
  </div>
</div>
```

Контракты атрибутов:
- `data-vcc-anchor` — слаг `[a-z0-9-]` (генерируется `VccExport.slugify`),
  рантайм навесит `id` (§7.1);
- `data-vcc-bg` — путь по правилам `safeHref` (`image/...`, `/...`, `https://...`);
- `data-vcc-bg-video` — url видео; poster = `data-vcc-bg`, если задан.
  Фон — только прямой mp4-файл (`https://…/bg.mp4` или `image/…`); видео из
  сервисов (iframe-вставка) — это контентный блок `video` (§6.20), не фон.

Поля секции (общий набор `vccSectionFields()`, возвращает массив деклараций —
используется каждым блоком в `fields()`):

| key | label | type | значения |
| --- | --- | --- | --- |
| `sec.bg` | Фон секции | select | `none/light/surface/primary/image/video` |
| `sec.image` | Картинка фона (путь `image/...` или URL) | text | при `bg=image/video` |
| `sec.video` | Видео фона (URL .mp4) | text | при `bg=video` |
| `sec.overlay` | Затемнить фон | checkbox | даёт класс `--overlay` |
| `sec.padding` | Отступы | select | `s/m/l/xl` (48/80/112/160 px стек) |
| `sec.width` | Ширина контента | select | `narrow (720px) / default (1140px) / full` |
| `sec.anchor` | Якорь секции (для ссылок `#…`) | text | slug |

Хранение: `data.sec = {bg, image, video, overlay, padding, width, anchor}` —
общий вложенный объект (нормализатор данных не трогает — `vccNormalizeBlock`
пропускает `data` как есть). Рендер-хелпер: `VccSection.open(sec)` /
`VccSection.close()` / `VccSection.head(sec)` — в `src/blocks/landing.js`
(новый файл, добавляется в `FILES_ORDER` build/build.py после
`blocks/shortcodes.js`).

`width=full` в export.css: `.vcc-section--w-full .vcc-container { max-width: none; padding-left: 24px; padding-right: 24px; }` —
без 100vw-трюка (_landmine_ `mp-full-bleed` из AGENTS.md темы: полноширинность
вне контейнерной сетки — источник вылезания за экран). Секция уже блочная и
растягивается контейнером страницы; «full» = снять max-width с внутренней
обёртки `.vcc-container`.

### 5.2. Заголовок секции (`vcc-section__head`)

Обязательный helper: если `sec.eyebrow` / `sec.title` / `sec.text` непустые:

```html
<div class="vcc-section__head[ vcc-section__head--center]">
  <span class="vcc-eyebrow">Надзаголовок</span>
  <h2 class="vcc-heading vcc-section__title">Заголовок</h2>
  <p class="vcc-section__sub">Пояснение</p>
</div>
```

Поля: `sec.eyebrow` (text), `sec.title` (text, markdown inline),

### 5.3. `rows-editor` — новый generic-тип поля редактора

Обобщение существующего `tabs-editor` (src/ui/app.js:163). Декларация:

```js
{ key: 'items', type: 'rows-editor', label: '…', addLabel: 'Добавить…',
  max: 12,
  itemFields: [ { key:'title', label:'Заголовок', type:'text' },
                { key:'text',  label:'Текст',     type:'textarea', markdown:true }, … ],
  itemTitle: function (item, i) { return item.title || ('Элемент ' + (i+1)); } }
```

- `data[key]` = массив объектов (плоский JSON — проходит нормализатор);
- карточка элемента: заголовок-свернутая строка + кнопки ↑ ↓ удалить + поля
  `itemFields`, отрисованные существующим `makeField` (рекурсия на 1 уровень —
  только простые типы; вложенные rows-editor запрещены);
- commit — глубокая копия + `refreshEditor()` (паттерн tabs-editor сохранён);
- `tabs-editor` объявляется как частый случай `rows-editor`
  (`itemFields: [title, content]`, ключ `tabs`) — обратная совместимость
  данных блоков `tabs` не трогается: тип поля остаётся `tabs-editor`,
  внутренне он делегирует в `makeRowsEditor`.

Это ЕДИНСТВЕННАЯ механика повторяющихся элементов v0.5.0 (шаги, тарифы,
команда, логотипы, …) — без неё каждый блок имел бы 6 ручных numbered-полей.

### 6.20 `video` — Видео из сервиса (vcc-video)

Штатный способ: пользователь берёт из видеосервиса «Поделиться → Встроить»
обычный iframe-код (или просто ссылку на ролик) и вставляет в поле. Санитайзер
темы НЕ пропускает `iframe`/`script` в контенте (решение по безопасности,
снимать его нельзя), поэтому конструктор извлекает из кода URL плеера и
экспортирует заглушку с `data-vcc-video` — iframe собирает рантайм темы (§7.5),
уже после санитайзера. Для пользователя результат идентичен стандартной
iframe-вставке.

Почему не «вставить iframe как есть», если путь A (код-вью) его не режет
(§3.0): экспорт должен быть идентичен на обоих путях внедрения — файл с
литеральным `<iframe>` пережил бы вставку в код-вью, но потерял бы видео при
импорте через кнопку (путь B), и контент перестал бы быть переносимым между
магазинами. Заглушка + рантайм работают везде одинаково. Если кому-то нужен
сервис только со скриптовой вставкой — это делается без конструктора: кусок
кода в поле «Custom JS» модуля или отдельная вставка в код-вью (решение
владельца магазина, не данные экспорта).

- fields:
  - `src` (textarea, rows 3) — placeholder: «Ссылка на видео или полный
    iframe-код из „Встроить“ сервиса». Парсинг в редакторе (`VccVideo.resolve`):
    1) `<iframe … src="…">` в вставленном коде → извлекаем `src`;
    2) обычная ссылка сервиса → нормализуем в embed-URL
       (youtube.com/watch?v=ID → `https://www.youtube-nocookie.com/embed/ID`,
       youtu.be/ID → то же; vimeo.com/ID → `https://player.vimeo.com/video/ID`;
       rutube.ru/video/ID → `https://rutube.ru/play/embed/ID`;
      ok.ru/video/… → `https://ok.ru/videoembed/ID`; dailymotion.com/video/ID →
      `https://dailymotion.com/embed/video/ID`; vk video_ext-URL проходит как есть);
    3) вставлен `<script>`-виджет без iframe → `showToast` (warning): «Видео
       через скрипт добавить нельзя (запрещено политикой безопасности темы) —
       скопируйте iframe-код или ссылку»;
  - `ratio` select `16x9 | 4x3 | 1x1`; `title` (text — name-of-video для `title` iframe и ссылки-заглушки).
- allowlist хостов embed (ЕДИНЫЙ список валидируется и конструктором, и
  рантаймом темы): `www.youtube-nocookie.com`, `player.vimeo.com`, `rutube.ru`,
  `ok.ru`, `www.dailymotion.com`, `vk.com/video_ext.php`. Чужой хост → блок
  экспортируется ссылкой (см. экспорт) и `showToast` при экспорте.
- model: `data.video = { url, ratio, title }` (url — канонический embed-URL
  после резолвера; сырой вставленный код не храним).
- экспорт (в секции §5.1; секция у блока служебная: bg по умолчанию `none`,
  padding `m` — видеоролик часто ставится внутрь соседней секции-текста, но
  архитектурно это самостоятельная секция):
```html
<div class="vcc-video vcc-video--{ratio}" data-vcc-video="{url}" data-vcc-video-title="{title}">
  <a class="vcc-video__link" href="{url}">{title|url}</a>
</div>
```
  Ссылка внутри — фолбэк без JS (работает: `a/href` пропускаются, ведёт на сам
  ролик); рантайм заменяет её iframe. Не-allowlist url (вручную подправленный
  JSON) → iframe не строится, остаётся ссылка.
- CSS: aspect-ratio-заглушка до/после сборки превью
  (`.vcc-video--16x9 { aspect-ratio: 16/9 }` и т.д.), `.vcc-video__frame,
  .vcc-video__link { position:absolute? }` — нет: контейнер `position:relative`,

### 7.3 `common.js` — фоны секций (image + video)
```js
$ctx.find('.vcc-section[data-vcc-bg]').each(function() {
	var url = $(this).attr('data-vcc-bg');
	if (/^(image\/|\/|https?:\/\/)/i.test(url)) $(this).css('background-image', 'url(' + url + ')');
});
$ctx.find('.vcc-section[data-vcc-bg-video]').each(function() {
	var src = $(this).attr('data-vcc-bg-video');
	if (!/^https?:\/\/|^\/|^image\//i.test(src)) return;
	var poster = $(this).attr('data-vcc-bg') || '';

});
```
Рантайм-созданные элементы существуют ПОСЛЕ санитайзера — ограничение

autoplay-политики браузеров соблюдены (`muted playsinline`).

```js
	e.preventDefault();
	var $m = $('#vita-form-modal-' + $(this).attr('data-vcc-form'));

});
```
- Требование к контенту: на той же странице обязан быть блок `vita_form`
  (шорткод рендерит `#vita-form-modal-N` — `common/vita_form_modal.twig:2`);
  без модалки клик молчит (грациозно).

### 7.5 `common.js` — контентное видео `[data-vcc-video]` (§6.20)
```js
var VCC_VIDEO_HOSTS = /^(https:\/\/)?(www\.youtube-nocookie\.com|player\.vimeo\.com|rutube\.ru|ok\.ru|www\.dailymotion\.com|vk\.com\/video_ext\.php)/i;
$ctx.find('.vcc-video[data-vcc-video]').each(function() {
	var $w = $(this), url = $w.attr('data-vcc-video');
	if (!VCC_VIDEO_HOSTS.test(url)) return; /* чужой хост — остаётся ссылка-фолбэк */
	var t = $w.attr('data-vcc-video-title') || 'Видео';
	$w.empty().append($('<iframe>').attr({
		src: url, title: t, loading: 'lazy',
		allow: 'accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; fullscreen',
		allowfullscreen: 'allowfullscreen'
	}).addClass('vcc-video__frame'));
});
```
iframe живёт только в DOM рантайма (после санитайзера) — в хранимом контенте
его нет, whitelist санитайзера (`iframe` запрещён) не ослабляется.

## 13. Журнал решений

| Решение | Обоснование |
| --- | --- |
| Тilda-модель: каждый широкий блок = своя секция, без рекурсии | плоская нормализация данных, нет row/col-ловушек |
| Фоны/видео/иконки/якоря через `data-vcc-*` + рантайм common.js | санитайзер: нет id/style/video; прецеденты TOC и tabs |
| `form:N` зеркально `agree:` в safeHref | минимальная аддитивная правка, грациозная деградация |
| rows-editor как обобщение tabs-editor | один паттерн повторения, отступов/порядка достаточно |
| Акцент `==текст==` | inline-окрашивание слов из бенчмарка demo-ydy |
| Звёзды reviews — unicode ★/☆, свой `.vcc-stars` в export.css | стандарт Виты (AGENTS), не лезем в `.vita-stars` витрины |
| Цена тарифа — строка | диапазоны «от 990 ₽» из бенчмарка, без механик |
| Два dark-оверрая максимум, остальное через фликающиеся токены | контракт fallback == vita.css :root; ловушка `--mp-primary-light` |
| `vcc-divider` без `hr` | равномерность отступов на div проще в контракте |
| `vita_html` как клапан | точечная кастомная вёрстка без новых блоков |
| Пресет landing-saas.json автозагрузкой билда | правок build.py нет |
| Видео сервисов = iframe-рантайм из `data-vcc-video` (решение владельца 2026-09-20: «видео добавляем стандартно, как отдают сервисы») | пользователь вставляет обычный iframe-код/ссылку; `iframe` в хранимом контенте остаётся запрещённым — whitelist санитайзера не ослабевает; script-виджеты невозможны физически |
| Поток внедрения = вставка экспорта в модуль «Вита — HTML» в режиме исходного кода (путь A, владелец 2026-09-20); экспорт по-прежнему проектируется под whitelist пути B (импорт-файл) | A не фильтруется вообще, B фильтрует — чтобы один файл не расходился между путями и контент оставался переносимым; сервисные script-коды — в «Custom JS» модуля, не в экспорт |
