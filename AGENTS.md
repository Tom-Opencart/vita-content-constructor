# Вита — Конструктор контента (vita-content-constructor)

Публичный самостоятельный продукт: визуальный конструктор контента, заточенный
исключительно под тему **Вита** (OpenCart 3). Живёт на GitHub Pages; тема позже
получит ссылку на него. Результат работы пользователя — файл бэкапа, который
импортируется в модуль «Вита — Универсальные блоки контента» (`vita_extra_html`).

Родительский релизный репозиторий темы — **приватный** и живёт отдельно; сюда
не переносится НИЧЕГО из него (см. «Публичная гигиена»).

## Три контракта (фиксируются, не ломаются)

### 1. Контракт экспорта `vcc-v1`

Каждый экспорт несёт маркер контракта в трёх местах:

- HTML: первая строка `<!-- Вита — Конструктор контента | контракт: vcc-v1 -->`;
- CSS: файл `css/export.css` — ЕДИНСТВЕННЫЙ источник экспортных стилей,
  заголовок объявляет контракт;
- JSON: поле `contract: "vcc-v1"`.

Правила эволюции:

- Внутри контракта изменения **только аддитивные**: новые блоки, новые классы,
  новые правила. Менять/удалять существующие классы `vcc-*` запрещено — на
  живых магазинах уже есть статьи с этим CSS (тема поставляет
  `vita-content-constructor.css` версионно).
- Смена контракта = новый неймспейс `vcc-v2` + новый CSS-файл в теме.
- Классы экспортной разметки — только `vcc-*`. Классы админки темы, Bootstrap
  или `mp-*` утилиты темы в экспорт НЕ попадают.

### 2. Контракт стилей: токены, никакого «нейрослопа»

- Все цвета/радиусы/тени экспортных правил — ТОЛЬКО `var(--mp-*, fallback)`.
  Литеральные hex/rgb в правилах `css/export.css` запрещены (fallback в var —
  исключение).
- Значения по умолчанию (fallback) = дефолтная палитра `vita.css` (`:root`).
  Список токенов — в `src/core/tokens.js` (`VCC_DEFAULT_TOKENS`), при изменении
  палитры в теме обновлять его в том же коммите, что и изменения токенов здесь.
- Тёмная тема: `[data-theme="dark"]` темы переопределяет поверхности/текст.
  Конструктор повторяет это через `VCC_DARK_TOKENS`; блоки НЕ имеют собственных
  тёмных переопределений — только токены.
- Цветовые значения блоков в модели данных — **имена токенов**
  (`primary`/`secondary`/`text`/`muted`), никогда hex. Пользователь физически не
  может выбрать цвет вне палитры магазина.

### 3. Контракт пресетов

Два типа JSON-файлов в `presets/`:

| Тип | `type` | Где лежит |
| --- | --- | --- |
| Пресет оформления (палитра магазина) | `vita-theme-preset` | `presets/themes/` |
| Готовый макет (контент) | `vita-constructor-project` | `presets/layouts/` |

Оба несут `contract: "vcc-v1"`. Пресет оформления несёт `tokens` — настройки
`theme_vita_color_*` из будущей кнопки «Экспорт пресета» темы; конструктор
маппит их на токены через `VCC_PRESET_MAP`, незнакомые ключи игнорирует.

При изменении схемы блоков (`src/core/schema.js`) все макеты в
`presets/layouts/` обновляются **тем же коммитом** — принцип «источник +
производное одним коммитом» из репозитория темы.

## Цепочка синхронизации с темой (жёсткое правило)

`css/export.css` этого репозитория и
`upload/catalog/view/theme/vita/stylesheet/vita-content-constructor.css`
в приватном репозитории темы — ОДИН ФАЙЛ. Тема подключает его автоматически
при выводе модуля «Универсальные блоки контента»; импортированный контент
не должен требовать никаких отдельных стилей (решение владельца 2026-09-19,
включая тёмную тему).

- Изменили `css/export.css` здесь → пересоберите `python build/build.py`
  → скопируйте файл в тему → коммит ОБЕИХ репозиториев в одной сессии.
- В теме работает автоматический гейт `vcc_sync_gate` (build_release.py):
  сборка темы ПАДАЕТ, если файлы различаются. Не пытайтесь править файл в
  теме отдельно — правится только источник здесь.
- Fallback-значения `var(--mp-*, fallback)` обязаны равняться `:root`
  vita.css темы (сверка при каждом изменении палитры, координированный
  коммит: vita.css + tokens.js + export.css fallbacks).

## Публичная гигиена (жёсткое правило)

Репозиторий публичный. Запрещено попадание сюда:

- любых файлов темы (twig, php, фрагменты `vita.css` как файлы);
- путей живых магазинов, доменов, токенов, скриншотов админок клиентов;
- клиентских фото и реальных названий магазинов (мок — только вымышленные
  данные: «Магазин „Вита“», example.com, плейсхолдер-картинки);
- лицензионного кода из чужих проектов без совместимой лицензии.

Стилизация под Виту выполняется ПО ТОКАМ (значения дефолтной палитры), а не
копированием CSS темы. Мок шапки/подвала рисуется с нуля в эстетике темы.

## Сборка и проверка

- `python build/build.py` — собирает `js/app.js` (IIFE, детерминированно,
  без timestamp). Исходники в `src/**`, собранный файл коммитится ВМЕСТЕ с
  правками исходников (Pages раздаёт репозиторий как есть).
- После изменений открыть `index.html` в браузере (Pages = `main`):
  - первый экран → «Начать с пустой страницы»;
  - добавить блоки каждого типа, проверить предпросмотр light/dark;
  - «Копировать HTML» → вставить в любую HTML-песочницу, вёрстка не должна
    зависеть от внешних стилей;
  - загрузить `presets/themes/*.json` — палитра применяется;
  - загрузить `presets/layouts/*.json` — макет открывается без ошибок.

## Стиль кода

- JS: TAB-отступы, ES5-совместимый синтаксис (функции, `var`, без стрелок и
  `let/const` — соразмерно оригинальному конструктору и старым админкам),
  строки в одинарных кавычках, `'use strict'` на файл.
- CSS: TAB-отступы, свойства по алфавиту внутри блока, один селектор на строку.
- Комментарии к секциям в стиле `/* --- Название --- */`.
- Никаких внешних зависимостей в рантайме, кроме CDN FontAwesome 4 (иконки).
- Секреты/ключи в репозитории невозможны по определению: приложение
  клиентское, без бэкенда. Не вводить аналитику/телеметрию без решения
  владельца.
